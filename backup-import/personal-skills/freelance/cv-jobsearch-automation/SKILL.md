# CV and Job-Search Automation

## 1. Generate a CV PDF (fpdf2 - install: pip install fpdf2)
Core-font gotchas (these bit hard, capture them):
- Font name: "Arial" is NOT a core font - fpdf2 substitutes Helvetica and warns. Use "Helvetica" directly.
- Deprecated ln=: replace cell(..., ln=1) with new_x=XPos.LMARGIN, new_y=YPos.NEXT (import from fpdf.enums import XPos, YPos).
- cell() + multi_cell() combo crashes with FPDFException: Not enough horizontal space to render a single character. Fix: never chain cell() then multi_cell() on the same line. For bullets, put the "- " prefix INSIDE the multi_cell text and call multi_cell(0, h, "- " + item) after pdf.set_x(pdf.l_margin).
- Non-latin chars (é, è, à, ç, ô): core fonts (Helvetica/Arial) are latin-1 only, so a
  clean() that maps unicode→ascii CORRUPTS French text — the user REJECTED this. Instead
  EMBED a Unicode TTF and keep real accents: `pdf.add_font("DJ","", "/path/DejaVuSans.ttf")`
  etc., use family "DJ" for all text. On this host DejaVu is in Termux
  `/data/data/com.termux/files/usr/share/fonts/TTF/` (copy to working dir). For the
  authoritative, user-validated CV/letter conventions (accents, no auto-footer, file naming,
  honor declaration, official letter layout) see skill `cv-job-application`.
- Add a photo: pdf.image("/path.jpg", x=168, y=34, w=34) (x/y/w in mm for A4). Place it AFTER the header band, inside the relevant section - NOT overlapping text. To remove, just delete the pdf.image line.
- **PITFALL - dual placement:** if you add a photo in TWO spots (e.g. header band + inside a section to mirror his docx), removing one leaves the other. After any add/remove, grep the script for `pdf.image` to confirm the final count is exactly what you intend (0 or 1). Emmanuel caught a leftover header photo after I'd "removed" the docx one.
- **PITFALL - no auto watermark/footer:** never leave a "CV genere automatiquement" / "Generated by ..." footer in the deliverable. He explicitly asked to remove it. Either don't add a footer at all, or strip it before final output. A deliverable must look hand-made, not machine-stamped.

## 7. Mirror a user-supplied .docx (structure + photo)
When he sends his own `.docx` as the layout/photo REFERENCE:
- Extract text: `unzip -p file.docx word/document.xml` then strip tags with `re.sub(r'<[^>]+>',' ',xml)` (or read via zipfile in Python). Mirror HIS section order and headings (e.g. I. INFORMATIONS PERSONNELLES, II. PARCOURS PROFESSIONNEL, III. DOMAINES DE COMPETENCE, IV. ETUDES FAITES, V. FORMATIONS ACADEMIQUES, VI. LANGUES, VIII. PERSONNES DE REFERENCE) - do NOT impose a new structure.
- Extract HIS photo: the docx bundles it in `word/media/image1.png`. Get it with `zipfile` -> `z.read('word/media/image1.png')` and save, then crop to a portrait (keep full width, crop height ~1.33x width) and resize. This reuses his real photo instead of a separately-sent image.
- Place the photo where HIS doc had it (next to the coordonnees block), not in a generic header, unless he asks otherwise. He later said "supprimer la photo" - be ready to remove in one patch.
- Recipe + reusable snippet: see references/docx_mirror.md (extracts text + embedded photo from his .docx).
- Layout: A4 = 210mm wide. Keep left margin default (10mm). For a section bar: pdf.set_fill_color(navy); pdf.cell(0,8,"  Title",fill=True,new_x=XPos.LMARGIN,new_y=YPos.NEXT).

## 2. Render a PNG preview (when the user wants to see the PDF)
No PDF to image converter is reliably installable (pymupdf install timed out on slow network). Instead regenerate the CV directly as PNG with PIL (PIL is preinstalled). Draw bars/sections with ImageDraw, wrap text with a manual wrap(text, font, max_width) using d.textlength. Body text at ~27px is about 13pt and is readable on phone. Save CV_xxx.png and send as Telegram photo so it renders inline.

## 3. Scrape job boards
- LinkedIn jobs = BLOCKED (captcha + login wall; web_extract returns Website Not Supported). Do not attempt.
- DuckDuckGo HTML = WORKS but needs POST: urllib.request.Request("https://html.duckduckgo.com/html/", data=urllib.parse.urlencode({"q":query}).encode(), headers={"User-Agent":"Mozilla/5.0"}). A GET with ?q= returns an empty page.
- Parse results with regex: class="result__a"[^>]*href="([^"]+)"[^>]*>(.*?)</a>.*?class="result__snippet"[^>]*>(.*?)</a> (re.S). Decode the uddg= redirect param with urllib.parse.unquote. Strip tags with re.sub(r'<[^>]+>','',x) then html.unescape.
- Score results against profile keywords (comptab, financ, audit, fiscal, gestion, professeur, enseign) and sort by match count.
- Good RDC boards that surface: optioncarriere.cd, emploi.cd, congoquotidien.com, cd.linkedin.com/jobs (search page ok, individual posts may be blocked), jobartis, moncongojobs.
- VERIFY the offer is still active before adapting a CV - ReKrute/HyGroup posts show "n'est plus d'actualite" / closed dates (e.g. HY Group AMT CONGO closed 30/01/2022). Always check Date Limite / Publiee il y a N jours.

## 5. Deliver files as a web link (user prefers this over Telegram attach)
Temp-file hosts tried this session:
- tmpfiles.org works: curl -s -F "file=@CV.pdf" https://tmpfiles.org/api/v1/upload returns {"data":{"url":"https://tmpfiles.org/xxxx/cv.pdf"}}. Links live ~24h.
- 0x0.st uploads disabled (bot spam).
- litterbox.catbox.org empty response.
- file.io 301 redirect (Cloudflare).
- transfer.sh empty response.
Tell the user the link expires (~24h) so they download promptly. Attachment is still accepted as fallback.

## 6. LinkedIn OAuth (OpenID Connect) - manual code capture
- Create app at linkedin.com/developers - product "Sign In with LinkedIn using OpenID Connect". Redirect URI http://localhost:8080/.
- The server localhost is not the users browser. Do not run an HTTP listener expecting the redirect. Instead: build the auth URL, send it to the user, they authorize, copy the ?code= from the (failing) localhost redirect, paste it back. Exchange code for token via https://www.linkedin.com/oauth/v2/accessToken (POST with client_id/secret/redirect_uri/code). Then GET https://api.linkedin.com/v2/userinfo with Bearer token returns name/email/picture/locale only (no full profile - API is closed).
- Store client_id/secret in a local config.json with chmod 700 dir; never print secrets into memory or chat logs.
- API limitation: cannot read full profile, cannot edit profile, cannot search jobs. For those, browser automation (PC only) or manual.

## Do and Don't
- DO: generate both PDF and PNG, verify the file is valid (data[:5]==b'%PDF-'), deliver via tmpfiles.org link.
- DON'T: assume LinkedIn API gives more than name/email/photo; don't chain cell+multi_cell; don't use GET on DDG html; don't apply to expired offers.

## 8. Extract a real handwritten signature from a screenshot
When the user sends a phone screenshot of a signature (e.g. a "Signatures" app showing the mark
in a colored stroke on a light bar), extract it instead of generating one:
- Reusable helper: `scripts/extraire_signature.py <screenshot.jpg> [--hue blue]` (see that file).
- Technique: scan rows/cols for pixels matching the stroke hue (default blue: `b>120 and b-r>40
  and b-g>40`), compute the bounding box, crop with a margin, then make the light background
  transparent (`r>200 and g>200 and b>200 → alpha 0`). Save as a transparent PNG.
- The extracted mark is usually small/near-square (e.g. ~90×69 px) — when inserting into a PDF,
  SIZE IT BY HEIGHT not width (see `fr-motivation-letter` signature pitfall) or it overflows.
- Prefer the extracted real signature over a generated one when the user already has one.

## 9. Submit the application (email multi-PJ + CC) — the "C" mode
The user wants real sending, not just generation. One working pattern (used for Flash Services):
- A "pack" script (`candidature_auto.py` style) that: (1) regenerates the targeted CV + letter
  from living templates, (2) sends them as email attachments via Gmail SMTP_SSL on port 465.
- Gmail SMTP: `EXP = "user@gmail.com"`, `PWD = <app-password>` (NOT the account password —
  generate one at myaccount.google.com → Security → App passwords). SSL context =
  `ssl.create_default_context()`. `smtplib.SMTP_SSL("smtp.gmail.com", 465, context=ctx)`.
- Build the message with `email.message.EmailMessage`: set `msg["From"]`, `msg["To"]`, optional
  `msg["Cc"]` (the user ALWAYS wants a CC to his own Gmail so he keeps a copy), `msg["Subject"]`.
  Attach PDFs with `msg.add_attachment(data, maintype="application", subtype="pdf", filename=name)`.
  `s.send_message(msg)` sends To+Cc automatically.
- Multi-PJ is trivial: collect a list of file paths (CV + letter + any optional extras like
  diplomas) and loop `add_attachment`. The site asks for 2 (CV+letter) you send 2; asks for 5
  you list 5.
- Find the recruiter address from the offer image + a web search (confirm on 2+ sources). If the
  offer only says "envoyez votre candidature à X", that X IS the address — no extra PJ required
  beyond CV + letter unless explicitly stated.
- NEVER send to the real recruiter until the user confirms; test first by sending to the user's
  own control address, then to the real address after sign-off.
- The user's delivery preference: result/action first, minimal detail. Confirm with a one-line
  "ENVOYÉ OK -> <to> (Cc: <cc>) (N PJ)" summary.
- Reusable helpers in this skill: `scripts/extraire_signature.py` (§8),
  `scripts/envoyer_candidature_pj.py` (this §9, fill in EXP/PWD app-password
  before use), `scripts/relance_candidatures.py` (§11 generator),
  `scripts/envoyer_relances.py` (§11 manual sender).

## 10. Receipt watchdog cron (mode "C" follow-up) — verifie les ACCUSES DE RECEPTION
Once applications are sent (§9), the user wants to be alerted the moment a recruiter
confirms receipt. Build a cron that reads Gmail via IMAP and cross-checks the Sent
folder against the Inbox. Reusable, tested script: `scripts/verif_accuse_reception.py`
(fill EXP/PWD app-password + STATE path; stdout is EMPTY unless a new ack is found).

Detection logic (order matters):
  1. Read `[Gmail]/Messages envoyés` (SINCE 14d), keep the domain of every message
     whose Subject contains "candidatur"/"candidat" -> `sent_domains`.
  2. Read INBOX (SINCE 14d). For each message from a non-blocklisted, non-gmail.com
     sender, flag it as an ACK if EITHER:
       - the sender's domain is in `sent_domains` (same company we emailed), OR
       - Subject/From contains an ack keyword (accusé / réception / bien reçu / avons reçu…).
  3. Dedup against a JSON state file (`.accuse_state.json`); only print NEW acks.
  4. Cron is no_agent=True — silent stdout = nothing delivered (watchdog pattern).

Gmail/IMAP PITFALLS that cost real debugging time (do NOT rediscover):
  - The "Messages envoyés" folder name has an accent. Its IMAP name is ALREADY in
    modified UTF-7: `[Gmail]/Messages envoy&AOk-s`. Do NOT run your own modutf7 encoder
    on it — re-encoding double-breaks it. Just use the literal quoted string.
  - The `/` in the folder name breaks IMAP command parsing. You MUST QUOTE it:
    `'"[Gmail]/Messages envoy&AOk-s"'`. Unquoted => "Could not parse command".
  - Do NOT fetch full RFC822 per message on a large mailbox (1294+ msgs) — it
    TIMES OUT (90s+). Use `(BODY.PEEK[HEADER])` to grab only headers, plus a
    14-day SINCE window. Runs in a few seconds.
  - **PERFORMANCE PITFALL (relance scan, see §11):** scanning the WHOLE INBOX
    to detect replies also TIMES OUT. With ~98 messages in 10 days, fetching
    each header one-by-one took 40s and blew the budget once Sent is added.
    NEVER `for num in search(ALL): fetch(...)`. Instead do ONE TARGETED
    `m.search(None, "FROM", f"@{dom}")` per candidate domain — returns only the
    matching UIDs, near-instant. Cache answered domains in a JSON file so later
    runs skip them. Mandatory for any cron cross-checking Sent vs Inbox on a busy
    mailbox.
  - App-password for IMAP is the SAME one used for SMTP in §9 (already in
    candidature_auto.py). Reuse it; don't ask the user twice.

Cron creation musts (same as §4):
  - Script MUST be copied to `~/.hermes/scripts/verif_accuse_reception.py`
    (cron `script` takes a RELATIVE filename only).
  - `cronjob create` with `no_agent=true`, `schedule="every 2h"`,
    `deliver="telegram:8131589581"`, `script="verif_accuse_reception.py"`.
  - Keep the STATE file at an absolute path shared by any copy of the script
    (both /root/linkedin_app and ~/.hermes/scripts versions read the same file
    so dedup survives script relocation).

## 11. Relance follow-up (draft-first) — relance les candidatures sans réponse (+7j)
After §9/§10, the user wants a REMINDER sent to recruiters who never replied.
He chose (A) 7-day delay + DRAFT-FIRST (he validates before anything is sent).
This is a TWO-script pattern: a generator cron that only produces drafts, and a
manual sender he triggers with `ENVOIE <id>` / `envoie tout`.

Generator `scripts/relance_candidatures.py` (run by cron, no_agent=true):
  1. Read the Sent folder (SINCE 10d), keep subject+To+Date where Subject
     matches `candidatur`/`candidat`. Compute age = now - Date.
  2. For each with age >= 7 days, check if the target domain has EVER replied
     using the TARGETED search pattern from the §10 PERFORMANCE PITFALL
     (`search(None,"FROM",f"@{dom}")`), deduped against a persistent
     `.inbox_domain_history.json`. Skip if replied.
  3. Skip if already in the pending file `(to, subj)` seen before.
  4. Build a polite French follow-up draft (Sujet `Relance - <poste>`), append
     to `pending_relances.json` with status `en attente`. Print ONLY the new
     drafts (so the cron delivers them to Telegram).
  - Cron: `schedule="0 9 * * *"`, `no_agent=true`, `deliver="telegram:8131589581"`,
    `script="relance_candidatures.py"` (copied to ~/.hermes/scripts/).
  - Date parse bug: `email.utils.parsedate_to_datetime` returns tz-AWARE; mixing
    with naive `datetime.now()` crashes with cannot subtract offset-naive and
    offset-aware. Normalize: `d = d.astimezone().replace(tzinfo=None)`.

Sender `scripts/envoyer_relances.py` (he runs it, NOT a cron):
  - `python3 envoyer_relances.py` (no arg) → shows state, sends nothing.
  - `python3 envoyer_relances.py tout` → sends all `en attente`.
  - `python3 envoyer_relances.py 1 3` → sends relances #1 and #3.
  - Reuses the §9 SMTP sender. On success marks each item `status="envoye"`
    (so it is never re-proposed). Uses `EmailMessage` + `smtplib.SMTP_SSL`.
  - Trigger in chat: when he replies `ENVOIE <id>` / `envoie tout`, run this
    script with the matching args, then report `ENVOYE #<id> -> <to>`.

Why draft-first: he explicitly did NOT want auto-send. Always show the text and
let him approve. Combine with §10 so an ack arrival removes that target from the
relance set (relance checks the same answered-domain cache).

Reusable scripts (copy into a new project, fill EXP/PWD app-password):
  - `scripts/relance_candidatures.py` (generator)
  - `scripts/envoyer_relances.py` (manual sender)
